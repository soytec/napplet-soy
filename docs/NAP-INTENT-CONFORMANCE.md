## Installed binding audit

No package upgrade is required for the audited INTENT envelope shapes or normalization behavior.

`intent-binding.test.ts` evaluates that published production bundle, installs the domains in a test window and invokes its actual API. It checks URI-derived fields, bare named naddr decoding, queryless structured payload plus fragment, invalid/conflicting fragment and payload rejection, percent decoding errors, duplicate decoded names, literal plus, `open` action restriction, availability/handler results, changed subscription closure and retained delivery. INC is installed only in this isolated test to check rejection of fragments by other convention APIs; production INC support is not added.

All three public manifest kinds install through the shared signature/manifest validator. Source identities without advertisements remain valid endpoints. Named/root identities remain stable across releases, differ by publisher/kind and preserve case-sensitive opaque `d`; snapshots remain signed-event-specific.

## Current host bounds and unresolved compatibility

IN-01 validates a hint coordinate up to 1024 characters, at most eight relay hints and at most 2048 characters per hint. Relay strings remain discovery inputs, not approved destinations; network policy must validate them when IN-03 uses them. Hint coordinates preserve opaque d including case and colons. Extra caller fields are omitted from the normalized copy.

The existing host convention parser rejects whitespace/control characters and malformed percent encoding and bounds identity to 1024 characters. The published normalizer accepts some segment strings outside that host subset. Document and test these as host policy during IN-02/05; no full unqualified URI-acceptance claim follows from the audit.

The published receiver buffers deliveries without an exposed buffer quota. Current workspace limits bound pending host delivery, not the cumulative receiver-side retention after dispatch. IN-04/05 must qualify this distinction; no new wire acknowledgement is available or invented.

Recommendation selection remains unimplemented: IN-01 retains validated hints for subsequent selection work but does not use them to choose targets. Availability injection and SHELL independence are locally implemented/verified in IN-02; launch/catalog coherence remains open. Full-support claims require the remaining plan gates, including packaging and browser tests.

## IN-02 evidence — 2026-10-13

`prelude.test.ts` evaluates the installed production bundle with supported/unsupported surface domains and proves that private document readiness follows namespace installation. Required INTENT admission rejects on an unsupported surface. `intent-host.test.ts` now verifies the official correlated result and retained cold delivery with private document readiness and no SHELL traffic, including wrong/foreign signals, repeated readiness and endpoint retirement.

`tests/services/intent-readiness-browser.test.ts` builds the shared host and installed shim, then runs two Chromium scenarios with actual signed named manifests and hash-verified HTML in the production opaque sandbox. It deliberately omits the optional SHELL supplement. Discovery/invocation, cold delivery, delayed receiver subscription after source closure, namespace omission, required-domain rejection, unready/foreign signal rejection and navigation retirement all pass. Earlier capture-phase retirement listeners remain effective when creator code attempts to suppress lifecycle events. These fixtures are not the complete web/preview UI or public-discovery test planned for IN-05.

Frame lifecycle messages (`soy.frame.ready`/`soy.frame.retired`) are private host bootstrap traffic with document-session/source/origin checks, not new NAP messages or application-visible acknowledgement contracts. INTENT uses its unchanged standard envelopes. Other domains retain their existing SHELL initialization behavior. Runtime profile `space-playback-7` records changed admission; upstream pins are unchanged.
